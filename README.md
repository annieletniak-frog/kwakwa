# Отчётник

Мини-приложение для еженедельных отчётов команды UX-райтеров. Райтеры заполняют отчёт по единой форме,
тимлид проверяет, дополняет и комментирует, а затем одной кнопкой копирует общий отчёт для Confluence.

## Самый простой запуск — через Google

Если рабочая почта в Gmail (Google Workspace), приложение можно запустить самостоятельно и бесплатно:
отчёты хранятся в Google Таблице, вход через рабочий Google-аккаунт. Пошаговая инструкция —
[google/README.md](google/README.md). В Google-версии есть и Slack: напоминание в канале по четвергам
и отбивки райтерам после проверки отчёта. Ниже описана версия с собственным сервером (без Slack).

## Что умеет

- **Вход по рабочей почте**: одноразовый 6-значный код приходит на почту. Войти могут только адреса из
  списка команды (`config/team.json`), одного адреса без кода недостаточно. Роль определяется учётной записью.
- **Вкладка «Райтер»**: выбор отчётной недели, проект из списка (`{brand} Main`, `WL`, `Side Project`, `W.tv`,
  `CDP`, `Landings`), название стрима, разделы «Завершено», «Блокеры», «Что в работе» (с датой или ближайшей
  вехой), «Важные встречи и обсуждения». Кнопки «Добавить задачу», «Добавить стрим», «Добавить проект», «Сохранить».
- **Вкладка «Тимлид»**: кто заполнил отчёт за неделю, открытие отчёта любого райтера, правка и дополнение задач,
  комментарии к конкретной задаче, предпросмотр общего отчёта и кнопка «Скопировать общий отчёт».
- **Правки видны райтеру**: задачи, добавленные или изменённые тимлидом, отмечены (с прежним текстом),
  удалённые задачи перечислены отдельно, комментарии показаны под задачами.
- **Вкладка «История»**: сохранённые отчёты по неделям. Райтер видит только свои, тимлид — все и общий отчёт.
- **Общий отчёт**: `🔹 UX Writers → проект → стрим → «Завершено» / «Блокеры» / «Что в работе» / «Важные встречи и обсуждения» → задачи списком`.
  Записи разных райтеров объединяются по проекту и стриму (регистр и пробелы в названии стрима не важны),
  пустые разделы и пункты не выводятся. В буфер копируется HTML с заголовками и списками (Confluence сохраняет
  форматирование при вставке) и текстовый вариант.

Вне этой версии: роль дизайнера (в `team.json` её можно указать, но доступа она пока не даёт), автоматическая
публикация в Confluence, напоминания и уведомления по почте, автонаписание отчёта.

## Быстрый старт на вымышленных данных

Нужен Node.js 20+.

```bash
npm install
npm run demo
```

Откройте http://127.0.0.1:3000 и войдите, например, как `anna@example.com` (райтер) или `lead@example.com`
(тимлид). В демо-режиме письма не отправляются: код входа печатается в консоль сервера. Демо создаёт
`config/team.json` из примера и вымышленные отчёты за две прошлые недели.

## Настройка

`config/team.json` (в git не попадает, образец — `config/team.example.json`):

```json
{
  "allowedDomains": ["company.com"],
  "projects": ["{brand} Main", "WL", "Side Project", "W.tv", "CDP", "Landings"],
  "users": [
    { "email": "lead@company.com", "name": "Имя Фамилия", "role": "lead" },
    { "email": "writer@company.com", "name": "Имя Фамилия", "role": "writer" }
  ]
}
```

Файл перечитывается при изменении: убранный из списка человек теряет доступ сразу, без перезапуска.

Переменные окружения:

| Переменная | По умолчанию | Назначение |
|---|---|---|
| `PORT`, `HOST` | `3000`, `127.0.0.1` | Где слушать. По умолчанию только localhost |
| `DATA_DIR` | `./data` | Хранилище отчётов и сессий (JSON, ежедневные копии в `data/backups/`) |
| `TEAM_FILE` | `./config/team.json` | Список команды |
| `MAIL_MODE` | `smtp`, если задан `SMTP_HOST`, иначе `console` | `console` запрещён при `NODE_ENV=production` |
| `SMTP_HOST`, `SMTP_PORT`, `SMTP_USER`, `SMTP_PASS`, `SMTP_SECURE`, `MAIL_FROM` | — | Отправка кода входа |
| `COOKIE_SECURE` | `true` в production | Cookie только по HTTPS |
| `TRUST_PROXY` | `false` | Учитывать `X-Forwarded-*` от своего обратного прокси |

## Проверка

```bash
npm test
```

Тесты покрывают вход и одноразовость кода, блокировку перебора, защиту от CSRF, разграничение доступа
(райтер не видит чужие отчёты и общий отчёт), видимость правок и комментариев тимлида, конфликт одновременных
правок, сохранение данных и сессий после перезапуска, отзыв доступа и формат общего отчёта.

Сценарий приёмки по ТЗ:

1. Все 6 райтеров входят и заполняют отчёт за неделю.
2. Тимлид во вкладке «Тимлид» видит «Заполнили 6 из 7», открывает отчёты, дополняет и комментирует задачи.
3. Райтер после повторного входа видит правки и комментарии у себя и во вкладке «История».
4. Тимлид нажимает «Скопировать общий отчёт», вставляет его в Confluence и публикует.
   Замер: время от открытия вкладки «Тимлид» до публикации страницы — цель не более 15 минут.

## Безопасность и данные

- До согласования хранения и доступа работаем только на вымышленных данных (`@example.com`).
  Реальные отчёты не кладём в код, примеры, тесты и запросы к ИИ-агентам.
- Все данные отдаются только через API после входа и проверки роли; сама страница данных не содержит.
  Чужой отчёт для райтера неотличим от несуществующего.
- Сессия — случайный токен в cookie `HttpOnly; SameSite=Strict; Secure`, на сервере хранится только его хеш.
  Код входа хранится в виде хеша, живёт 10 минут, допускает 5 попыток; запросы кода и попытки входа ограничены.
- Строгий CSP, запрет встраивания во фреймы, `noindex` для поисковиков, `robots.txt` с запретом индексации.
- Решение о месте размещения, составе пользователей и запуске с реальными данными принимает ответственный человек —
  см. [docs/DEPLOY.md](docs/DEPLOY.md).

`assets/video/`; видео с YouTube подключать ссылкой.

```

docs/     DEPLOY.md — вариант размещения
```
