# Вариант размещения

Документ для ответственного за запуск. Агент подготовил приложение и предложение; место хранения, состав
пользователей и запуск с реальными данными подтверждает человек.

## Что нужно согласовать до запуска

- [ ] Данные принадлежат команде; хранить рабочие отчёты (без чувствительных данных) в выбранном месте разрешено.
- [ ] Место размещения приложения и хранилища (`DATA_DIR`).
- [ ] Способ входа: SMTP-сервер или почтовый ящик, с которого уходят коды входа.
- [ ] Состав пользователей в `config/team.json`: 6 райтеров и тимлид, домен в `allowedDomains`.
- [ ] Кто отвечает за резервные копии и удаление доступа ушедшим сотрудникам.

## Рекомендуемая схема

```
Сотрудник ── HTTPS ──▶ обратный прокси (nginx / корпоративный ingress) ──▶ Отчётник 127.0.0.1:3000
                       внутренняя сеть или VPN                           DATA_DIR на диске сервера
```

1. Внутренний сервер или ВМ компании, доступ только из корпоративной сети или через VPN.
   Публичный адрес без входа не защищает данные: страницу может открыть любой, у кого есть ссылка.
   В приложении данные доступны только после входа, но лучше не выставлять его в интернет вовсе.
2. HTTPS обязателен: без него cookie сессии с флагом `Secure` не будет работать, а кнопка копирования
   отчёта в некоторых браузерах недоступна.
3. Приложение слушает только `127.0.0.1`, наружу его открывает прокси.

### Запуск без Docker

```bash
npm ci --omit=dev
cp config/team.example.json config/team.json   # заполнить реальными адресами после согласования
NODE_ENV=production \
TRUST_PROXY=true \
DATA_DIR=/var/lib/otchetnik \
SMTP_HOST=smtp.company.com SMTP_PORT=587 SMTP_USER=... SMTP_PASS=... \
MAIL_FROM="Отчётник <no-reply@company.com>" \
node server/index.js
```

Для постоянной работы — unit systemd с `Restart=always` от отдельного пользователя без прав входа;
каталог `DATA_DIR` доступен только ему (`chmod 700`).

### Запуск в Docker

```bash
docker build -t otchetnik .
docker run -d --name otchetnik --restart=always \
  -p 127.0.0.1:3000:3000 \
  -v /var/lib/otchetnik:/data \
  -v /etc/otchetnik/team.json:/app/config/team.json:ro \
  --env-file /etc/otchetnik/env \
  otchetnik
```

### Фрагмент nginx

```nginx
server {
  listen 443 ssl;
  server_name otchetnik.internal.company.com;
  # ssl_certificate ...; ssl_certificate_key ...;
  # allow 10.0.0.0/8; deny all;   # только внутренняя сеть

  location / {
    proxy_pass http://127.0.0.1:3000;
    proxy_set_header Host $host;
    proxy_set_header X-Forwarded-For $remote_addr;
    proxy_set_header X-Forwarded-Proto https;
  }
}
```

## Хранение и резервные копии

- Отчёты — `DATA_DIR/reports.json`, сессии — `DATA_DIR/sessions.json`. Запись атомарная.
- Раз в сутки при первом сохранении предыдущая версия копируется в `DATA_DIR/backups/`.
  Каталог стоит дополнительно включить в штатное резервное копирование сервера.
- Хранилище рассчитано на одну команду (единицы пользователей, сотни отчётов в год).
  Если приложение начнут использовать несколько команд, стоит перейти на СУБД.

## Отзыв доступа

Удалите человека из `config/team.json` — доступ закроется при следующем запросе, без перезапуска.
Чтобы разлогинить всех, остановите приложение и удалите `DATA_DIR/sessions.json`.
